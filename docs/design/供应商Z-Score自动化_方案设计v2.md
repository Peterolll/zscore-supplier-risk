**⚠️ 季报陷阱实测（本基准的核心价值）：**

| 情形 | X3 (EBIT/TA) | X5 (REV/TA) | Z′ | 判定 |
|------|-------------|-------------|-----|------|
| A. 直接用单季数据（错误） | 0.0025 | 0.1532 | **1.428** | 灰色区（被低估） |
| B. 流量年化后（×4） | 0.0099 | 0.6127 | **1.910** | 灰色区（接近真实） |

> 同一家公司，仅因是否年化，Z′ 从 1.428 → 1.910，**差 0.48**。
> 若某公司恰在阈值附近，足以把"安全"错判成"灰色"，或反之。
> **结论：X3、X5 用的是流量数据（利润表），必须与资产负债表的时间口径对齐。**

| 销售收入 REV | 营业收入 | 2,761,977,833.25（全年） |

**✅ 年报路径实测（annualize_factor = 12/12 = 1，流量不年化）：**

```
X1 = (CA-CL)/TA = 1,030,377,900.28 / 4,542,833,529.92 = 0.2268
X2 = RE/TA      = 1,716,175,504.27 / 4,542,833,529.92 = 0.3778
X3 = EBIT/TA    =    58,625,743.28 / 4,542,833,529.92 = 0.0129
X4 = EQ/TL      = 2,987,807,257.16 / 1,555,026,272.76 = 1.9214
X5 = REV/TA     = 2,761,977,833.25 / 4,542,833,529.92 = 0.6080
Z′ = 1.9365 → 灰色区（1.23 < 1.94 < 2.9）
```

**🔁 与基准5（2026 Q1 季报）的交叉验证（本基准的核心价值）：**

| 样本 | 报告类型 | 处理方式 | Z′ | 风险区 |
|------|---------|---------|-----|--------|
| 基准6：2025 年报 | 年度报告 | **不年化**（factor=1） | **1.94** | 灰色区 |
| 基准5：2026 Q1 | 季度报告 | **流量 ×4 年化** | **1.91** | 灰色区 |

> 两份报告是**不同时点**（2025 全年 vs 2026 Q1），但 Z′ 仅差 **0.03** 且同落灰色区。
> 这等于用一份**独立年报**反向验证了「季报流量年化」路径的正确性——
> 若季报年化是错的，年报(不年化)不可能给出如此接近的结果。
> **结论：① 无年化路径跑通；② 季报 ×4 年化可信；③ 大陆 CAS 规则（RE拆分/利息嵌套/含少数股东X4）在年度数据上同样成立。**

### 2.2 与 v1.0 的关键架构差异

1. **M1 分类器独立成模块**：v1 把"探测"混在输入层，v2 独立出来，因为它决定了后续所有路由。
2. **M4 明确三级机制**：v1 只说"正则+LLM"，v2 明确为"词典→规则→LLM"三级递进，每级都有命中率和成本的量化预期。
3. **M5 独立验证器**：v1 只在风险里提了一句复式平衡，v2 把验证独立成模块，作为计算前的必经闸门。
4. **M7 三层输出**：v1 只有 Excel，v2 增加机器可读 JSON（供后续系统对接）和复核 HTML（供人工确认）。

### 3.1 核心提取结果 `ExtractionResult`

```json
{
  "supplier_id": "SUP-QSP",
  "supplier_name": "Qatar Site and Power W.L.L.",
  "report_period": "2023-12-31",
  "currency": "QR",
  "currency_unit": 1,
  "source_file": "QSP FS 2023.pdf",
  "fields": {
    "current_assets": {
      "value": 169667494,
      "confidence": 0.97,
      "method": "dictionary",
      "source_page": 5,
      "source_label": "Total current assets (derived)",
      "evidence": "Inventories 24,960,387 + Trade receivables 137,603,446 + Bank 7,103,661"
    },
    "current_liabilities": { "value": 37478444, "confidence": 0.95, "method": "rule", "source_page": 5 },
    "total_assets":      { "value": 173802193, "confidence": 0.99, "method": "dictionary", "source_page": 5 },
    "retained_earnings": { "value": 127737006, "confidence": 0.99, "method": "dictionary", "source_page": 5 },
    "ebit":              { "value": 2600796,   "confidence": 0.88, "method": "derived", "source_page": 4,
                            "derivation": "PBT 2579264 + Finance costs 21532" },
    "total_equity":      { "value": 132837006, "confidence": 0.99, "method": "dictionary", "source_page": 5 },
    "total_liabilities": { "value": 40965187,  "confidence": 0.99, "method": "dictionary", "source_page": 5 },
    "revenue":           { "value": 202627392, "confidence": 0.99, "method": "dictionary", "source_page": 4 }
  },
  "validation": {
    "balance_check": "pass",
    "balance_diff_pct": 0.0,
    "logic_check": "pass",
    "flags": []
  }
}
```

**设计要点：**
- 每个字段不仅存 `value`，还存 `confidence / method / source_page / evidence`——这是**可审计性**的关键，也是复核界面的数据基础。
- `method` 枚举：`dictionary | rule | llm | derived | manual`，用于统计各级命中率、优化成本。
- `currency_unit` 存换算系数（千元=1000），最终 Z-Score 是比值，单位抵消，但留存原始单位便于人类核对。

```json
    { "period": "2022", "z": 7.32, "band": "safe" },
    { "period": "2023", "z": 10.89, "band": "safe" }
  ]
}
```

**设计要点：**
- `industry_class` → `zscore_model` 是**自动选择模型**的依据（见第五部分）。
- `threshold_override` 允许针对特定地区/行业微调阈值（应对 Altman 美国样本的局限）。
- `history` 支撑跨年趋势分析（QSP 2022→2023 的 Z″ 从 7.32 升到 10.89，但利润下滑，提示需看结构）。

### 4.2 规则匹配（L2）

词典命中后，用规则解析数值并处理格式：

```python
# 数值清洗规则（覆盖4样本观察到的所有格式）
def parse_number(s):
    s = s.strip()
    neg = False
    if s.startswith('(') and s.endswith(')'):   # (5,500) 括号负数
        neg = True; s = s[1:-1]
    s = s.replace(',', '').replace('$', '').replace(' ', '')
    s = s.rstrip('%')
    v = float(s) if s not in ('', '-', '—') else None
    return -v if (neg and v is not None) else v
```

- 括号负数：`(2,100,106)` → -2100106（瀚荃、QSP 都用）
- 千分位：`4,620,715` → 4620715
- 空值占位：`-`、`—`、`空` → None（触发缺失修复，而非报错）
- OCR 容错：扫描件常把 `,` 识别成 `.`、把 `0` 识别成 `O`，需在 L2 加一层"数字合理性二次确认"（见第五部分 G3）。

## 第五部分：完善 — EBIT 推导决策树（替代 v1 单条规则）

Z-Score 的 X3 = EBIT/总资产，但"EBIT"在不同准则下口径不同。基于4样本的实际差异，建立决策树：

```
读取利润表
  ├─ 是否存在明确的 "EBIT" / "息税前利润" 行?
  │     └─ 是 → 直接采用
  │
  ├─ 否则，定位 "税前利润" (Profit before tax / 稅前淨利 / 利润总额)
  │     │
  │     ├─ 检查利润表中"利息/财务成本"是否在税前利润【之前】被扣除?
  │     │     │
  │     │     ├─ IFRS (QSP/瀚荃): Finance costs 列在 PBT 之前
  │     │     │     → EBIT = PBT + Finance_costs
  │     │     │     验证: QSP2023 2579264 + 21532 = 2600796 ✓
  │     │     │     验证: 瀚荃 484315 + 13375 = 497690 ✓
  │     │     │
    │     │     ├─ 大陆 CAS: "利润总额" 已扣"财务费用"(含利息)
    │     │     │     → EBIT = 利润总额 + 利息费用(取"其中:利息费用"子行, 非财务费用母行)
    │     │     │     验证: 鸣志 7685038.81 + 3658830.53 = 11343869.34 ✓
    │     │     │
    │     │     └─ 无利息科目 (麦弗瑞): Finance costs = 0
    │     │           → EBIT = PBT (亏损即负EBIT)
    │     │           验证: 麦弗瑞 EBIT = -7755 ✓
    │     │
    │     └─ 若找不到"利息费用"明细但确认有借款
    │           → 降级: 用 PBT 近似, confidence 降至 0.6, 标记"需人工确认利息"
    │
    └─ 交叉验证 (G4): 若现金流量表存在，用 "支付之利息" 佐证利息费用
          验证: 瀚荃现金流量表"支付之利息"13,863 ≈ 利息费用13,375 ✓ (差异为期末应付)
```

> 这棵决策树覆盖了5个样本的全部 EBIT 情形，且每一步都有基准值验证。

## 第五·五部分：新增 — 定期报告类型识别与流量年化（鸣志样本暴露的关键陷阱）

### 问题本质

Z-Score 的 X3 = EBIT/总资产、X5 = 营收/总资产，分子（EBIT、营收）是**期间流量**，分母（总资产）是**时点存量**。两者时间口径必须对齐到"年化"，否则 X3、X5 被系统性低估。

鸣志实证：2026 Q1 季报的流量数据只有 3 个月。

| 情形 | X3 | X5 | Z′ | 后果 |
|------|-----|-----|-----|------|
| 直接用单季（未年化） | 0.0025 | 0.1532 | 1.428 | 偏低 0.48 |
| 年化后（×4） | 0.0099 | 0.6127 | 1.910 | 接近真实 |

**若某公司恰在阈值附近，未年化足以把"安全"错判为"灰色"，把"灰色"错判为"破产"。**

### 报告类型识别规则

```
读取报告标题/期间标识:
  ├─ "年度报告" / "Annual Report" / "For the year ended" → 年报 (12个月, 不年化)
  ├─ "半年度报告" / "Interim Report" / "For the six months" → 半年报 (×2)
  ├─ "第一季度报告" / "Q1" / "For the three months" → 一季报 (×4)
  ├─ "第三季度报告" / "Q3" / "For the nine months" → 三季报 (×12/9)
  └─ 审计报告(非上市): 看 "For the year ended..." / "财政期间: 由...至..."
        ├─ 期间 = 12个月 → 不年化
        └─ 期间 < 12个月 → 按 12/月数 年化

大陆报表辅助信号: 利润表表头 "2026年1—3月" / "2026年第一季度" → 单季(×4)
```

### 年化处理规则

```
annualize_factor = 12 / 报告覆盖月数

对流量字段（EBIT, revenue）:  value_annualized = value × annualize_factor
对存量字段（CA, CL, TA, TL, EQ, RE）:  不年化，直接用时点值

注：RE(留存收益)是存量（期末余额），即使季报也不年化。
   只有 EBIT 和 revenue 两个流量字段需要年化。

保守策略：若报告类型识别置信度低，默认按年报处理(不年化)，
         并在输出中标注"假设年度数据，若为季报请人工复核"。
```

### 供应商主数据需新增字段

```json
{
  "report_type": "quarterly_q1",
  "period_months": 3,
  "annualize_factor": 4,
  "flow_fields_annualized": ["ebit", "revenue"]
}
```

> **实践建议**：供应商风险评估**优先使用年度审计报告**（流量即全年，无需年化）。
> 季报/半年报仅在无年报时作为过渡，且必须年化 + 标注"基于季度数据年化，存在季节性偏差风险"。

## 第六部分：新增 — 验证闸门与错误恢复

### 6.1 五道验证闸门

| 闸门 | 规则 | 失败时动作 |
|------|------|-----------|
| **G1 复式平衡** | abs(TA - (TL+EQ)) / TA < 0.5% | 标记不平衡，提示可能是 OCR 漏行或单位错误，转入人工复核 |
| **G2 逻辑一致** | CA ≤ TA；CL ≤ TL；EQ ≈ TA - TL (±1%) | 标记矛盾字段，降置信度 |
| **G3 数值合理** | 无 NaN；OCR 数字位数与同类公司量级一致（防 OCR 把 1,234,567 读成 1234567 或 1234.567） | 触发重 OCR（更高 DPI）或转 LLM |
| **G4 EBIT 交叉** | 利润表推导 EBIT 与现金流量表利息佐证一致 | 不一致则标记"利息口径待确认" |
| **G5 完整性** | Z′ 需 8 字段，Z″ 需 7 字段（无需 revenue） | 缺失字段走修复规则（6.2） |

### 6.2 缺失字段修复规则

| 缺失字段 | 修复策略 | 修复后置信度 |
|---------|---------|-------------|
| total_liabilities | = TA - EQ（复式恒等式） | 0.85（derived） |
| current_assets（无合计行） | 逐项流动资产求和（麦弗瑞情形：仅现金） | 0.80 |
| current_liabilities（无合计行） | 逐项流动负债求和（麦弗瑞：Accrued + Due to related） | 0.80 |
| retained_earnings | 若仅缺，可从权益变动表期末余额取 | 0.85 |
| finance_costs | 若确认无借款 → 0；若有借款但无明细 → 标记待确认 | 0.60 |
| revenue（Z″不需要） | 跳过，不影响 Z″ | — |

> 麦弗瑞正是靠这套修复规则才能算出 Z″：它没有任何"合计行"，全靠逐项求和 + 复式恒等式推导。

## 第七部分：新增 — 行业分类 → 模型自动选择

Z′（5因子，含资产周转率）适用制造业；Z″（4因子）适用非制造业/服务业。自动判断逻辑：

```
读 SupplierProfile.industry_class:
  ├─ "manufacturing" → Z′ (需 revenue, 8字段)
  └─ "service"/"trading"/"other" → Z″ (不需 revenue, 7字段)

若 industry_class 未知:
  启发式推断:
    ├─ 利润表含 "營業成本/COGS/Contract costs" 且有存货 → 偏制造/工程 → Z′
    ├─ 无存货、收入以服务为主 → Z″
    └─ 无法判断 → 默认 Z″(更保守, 不依赖revenue), 并同时计算Z′供参考

4样本验证:
  瀚荃(制造) → Z′=2.248 灰色, Z″=6.953 安全 → 用Z′(正确, 制造业应用5因子)
  QSP(IT服务) → Z″=10.891, Z′=3.740 → 用Z″, 两模型同向(皆安全)
  麦弗瑞(中介) → Z″=-0.163, Z′=-0.033 → 用Z″, 两模型同向(皆破产)
```

**容错设计：** 系统**同时输出两个模型的分数**，但以行业匹配的模型为主判定。当两模型结论冲突时（如瀚荃 Z′灰色 vs Z″安全），以匹配模型为准并标注"两模型分歧，建议人工关注"——这正是瀚荃的情形，Z′判灰色更符合其制造业属性。

```
输入: 一个文件夹, 内含 N 个供应商 PDF (命名建议: 供应商名_年度.pdf)
  │
```

## 第十二部分：完善 — 风险矩阵

| 风险 | 概率 | 影响 | 可执行缓解措施 |
|------|------|------|---------------|
| OCR 数字识别错误（,→. / 0→O） | 高 | 高 | G3 闸门做位数/量级校验；异常值触发 600 DPI 重 OCR；关键字段（TA/EQ/TL）强制 G1 复式校验 |
| 新地区科目名未入库 | 高 | 中 | L3 LLM 兜底 + 人工复核确认后**回写同义词库**（系统自学习） |
