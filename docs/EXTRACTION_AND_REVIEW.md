# 财报提取与证据复核

## 上传、读取和确认

支持 PDF、PPTX、Excel `.xlsx` / `.xlsm`；旧 `.xls` 请先另存为 `.xlsx`。多文件合并仅限 PDF。

Excel 原生读取全部 Sheet（包括隐藏表和空表），支持左右双栏、合并单元格、多层日期表头、“名称/项目/财务科目”等标题，以及缩进和空列。公式读取已保存的缓存结果，不执行宏或公式；无缓存时提示重算保存。未明确的金额列、本期空白、未知单位和未映射科目会进入核对清单，不使用上期数或零替代。

提取结果先保存为待确认建议；用户可修改、确认或取消。确认后才同步对应财务字段并重算。旧建议与当前字段冲突时拒绝采纳。取消会持久化，刷新后不重新出现。

详情页提供：

- **重新读取 Excel 全部 Sheet（无需 AI）**：用于重新解析旧批次，展示逐表读取结果；新建议不会覆盖已确认字段。旧提取快照保留在日志中。
- **AI 分析补全（缺失项）**、**重新核验全部**：展示旧值、新值和原文证据，只有确认后写入。
- **全过程日志**：定位提取、旋转、重试、复核、取消、采纳和重算。

## 视觉与文本模型

分类、方向判断和图像抽取使用 GLM-4V-Flash；自定义端点须提供该模型。PDF、PPTX 图片和网页复核共用图像处理，资产表按左右区域读取并保留表头和单位。方向、单位、局部模糊、缺失字段分别有限重试。

文本模型只在用户主动点击 AI 补全或复核时调用。设置页可读取当前 Key 的 `/models` 列表并选择模型。服务端精确校验模型 ID，地址构造和模型配置集中管理；更换端点或 Key 后旧目录失效。网络异常可使用同一配置下明确保存的目录，HTTP 权限错误不使用目录兜底。不要将供应商专有模型名硬编码到业务流程。

## 数值来源与 EBIT

字段保存原文件、页码或 Sheet/单元格、坐标、原始字符串、期间、单位及倍率；程序负责选列和换算。证据有歧义时显示未知或待确认，保留派生依赖。Excel 导出包含来源及未完整抓取清单。

EBIT 优先采用原文明示值，否则仅使用完整输入：

1. 税前利润 + 利息费用；
2. 净利润 + 所得税费用 + 利息费用。

财务费用可能包含利息收入抵减、汇兑损益、手续费等，不直接替代利息费用。“税前利润 + 财务费用”仅为页面参考估算，不自动写入 EBIT 或参与评级。人工修改组件会联动重算派生 EBIT；明确的原文/人工 EBIT 保留。

勾稽检查区分独立来源和派生来源，不用推导关系证明其自身。关键因子缺失时 Z 值与风险区为未知；生产流程不按供应商名称套用基准覆盖。历史批次使用自身报告元数据和文件快照。

## 验证与部署

使用 Node.js 22+（需内置 `node:sqlite`）和安装仓库 `requirements.txt` 的 Python 环境。

在仓库根目录：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python3 -m unittest discover -s tests -v
```

在 `zscore-web/`：

```bash
npm ci
npm run test:regression
npx tsc --noEmit --incremental false
npm run build -- --webpack
```

回归共 33 项 Python 和 18 项 Node/SQLite/API 测试，使用合成财务金额、临时文件和隔离数据库。外部模型响应使用模拟数据；部署后需使用自己的端点、Key 和实际财报验证模型权限与识别准确率。

业务数据库会进行增量迁移，升级前请备份。真实财报、数据库、API Key、本地诊断报告、原始模型日志及图片不应提交到 GitHub；沿用仓库忽略规则和部署访问控制。
