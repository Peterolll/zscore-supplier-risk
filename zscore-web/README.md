# Z-Score 供应商风险分析平台 — 用户手册 v2.0

> 版本：v2.0 | 更新日期：2026-08-19
> 适用范围：`zscore-web` Web 应用（Next.js 16 + Python 引擎）

基于 Altman Z-Score 模型的供应商财务风险分析系统，提供 **财报上传 → 自动解析 → Z 值计算 → 可视化 → 字典自审 → 多供应商对比** 的完整闭环。

---

## 功能总览

### 核心功能
- **多格式上传分析**：支持 PDF（电子文本 / 扫描件）、PPTX 财报，填写行业 / 期间 / 会计准则 / 币种，自动计算 Z 值
- **多文件上传 + PDF 合并**：同一供应商多份 PDF 可同时上传，服务端自动合并后统一处理
- **三级抓取链**：L1 直接科目命中 → L2 子指标求和 → L3 会计恒等式推算，逐级兜底确保数据完整性
- **字典自审闭环**：系统自动发现未识别科目，进入「待审面板」供人工确认后写回字典库
- **可视化详情**：SVG 仪表盘（Z 值区间）、因子分解柱状图、科目级溯源证据表、5 道校验门状态
- **人工手填 + 确认标注**：支持手动录入缺失字段并重算 Z 值；推算值标记「推算待确认」
- **供应商库管理**：历史记录归档、按供应商聚合多期分析、支持单删 / 批量删除（级联清理）
- **多供应商对比**：勾选多个分析批次，对比 Z 值区间与因子构成、分组子指标
- **上市 / 非上市双模型**：支持上市公司原始 Z 模型（5 因子含市值）与非上市 Z′/Z″ 模型切换

### 提取引擎
- **电子文本通道**：pdfplumber 提取文本与表格
- **扫描件 OCR**：GLM-4V-Flash 视觉 OCR，未配置密钥时返回明确「待处理」状态
- **序号防误抓**：当报表中存在大额数值时，自动过滤 1–999 的纯整数行号
- **EBIT 决策树**：PBT + 利息费用优先；无利息费用时用 PBT 单独推算

### 输出与导出
- **Excel 导出**：沿用现有计算器格式的风险排序表 + 因子明细 Sheet
- **JSON API**：完整 ExtractionResult + ZScoreResult，供下游系统消费
- **页面复核**：每供应商一页，字段 → 页码 → 原文 → 提取方式 / 置信度

## 运行环境

| 依赖 | 版本 / 路径 | 说明 |
|------|------------|------|
| Node.js | 22.x（内置 `node:sqlite`） | 开发用 22.22.2 |
| Python | 含 `zscore_pipeline` 依赖的 venv | 见下方 `ZSCORE_PYTHON` |
| GLM_API_KEY | 可选 | 仅扫描件 OCR 需要；缺省时扫描件返回「待处理」 |

## 快速启动

```bash
# 0. 获取代码
git clone <仓库地址> zscore && cd zscore

# 1. 准备 Python 引擎环境（仓库根目录执行）
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt

# 2. 进入 Web 工程并安装依赖
cd zscore-web && npm install

# 3.（可选）指定 Python 解释器
cp .env.example .env.local   # 默认会自动探测 .venv，通常无需修改

# 4. 启动开发服务器
npm run dev
# 打开 http://localhost:3000
```

### 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `ZSCORE_PYTHON` | 自动探测（仓库根 `.venv` → 系统 `python3`） | Python 解释器（需能 `import zscore_pipeline`） |
| `ZSCORE_WORKSPACE` | `zscore-web` 的上级目录 | 引擎 cwd，需包含 `zscore_pipeline/` 包 |

## 使用流程

### 1. 上传财报并分析

1. 首页点击「上传财报并分析」，选择文件（可多选）并填写：
   - **供应商名称**（同名自动归并到同一供应商）
   - **行业**：制造业 / 服务业（决定 Z′ 或 Z″ 模型）
   - **上市状态**：上市 / 非上市（上市使用含市值的原始 Z 模型）
   - **报告期**：年度 / 半年度 / Q1–Q4（非年度自动年化）
   - **会计准则**：CAS / IFRS / 台湾准则 / 香港准则 / 其他
   - **币种**（可选，仅作展示标注）
2. 支持的文件格式：
   - **PDF**：电子文本或扫描件均可
   - **PPTX**：PowerPoint 格式财报
   - **多文件上传**：同一供应商的多个 PDF 会在服务端自动合并
3. 提交后自动计算，跳转至分析详情页

### 2. 查看分析详情

分析详情页展示：

- **Z 值仪表盘**：SVG 区间图，直观显示安全 / 灰色 / 破产区
- **因子分解**：X1–X5 各因子柱状图 + 数值
- **科目溯源证据表**：每个字段的命中科目、页码、原文、提取方式（L1 / L2 / derived / manual）、置信度
- **校验门状态**：5 道闸门（G1 复式平衡、G2 字段完整度、G3 非负校验、G4 量级合理性、G5 符号一致性）
- **状态标记**：
  - `推算待确认`（黄色）：通过会计恒等式推算的值，建议人工核对
  - `待确认`（黄色）：手动录入或低置信度值
  - `已确认`（绿色）：人工确认或高置信度直接命中

### 3. 人工手填与重算

当自动提取结果有误或缺失时：

1. 在分析详情页，点击字段旁的编辑按钮
2. 手动输入正确数值
3. 系统自动重算 Z 值与风险区
4. 手填字段标记为 `manual` 方式

### 4. 数据字典管理

访问 `/dictionary` 页面：

- **字段卡片**：每个 Z-Score 字段对应的同义词列表，可直接编辑
- **指标树（FIELD_TREE）**：展开查看子指标及其别名
- **待审科目面板**：
  - 系统在分析过程中自动发现未识别的科目行（有数值但无法匹配到任何字段）
  - 这些科目会进入「待审面板」，展示科目名称、数值、来源页码、样本文件
  - 点击「确认写回」可将该科目作为新别名写入字典（需选择目标字段和类型：直接 / 子指标）
  - 点击「忽略」可跳过该科目

### 5. 供应商库管理

访问 `/suppliers` 页面：

- 查看所有供应商及其历史分析记录
- 点击供应商查看详情页，展示多期 Z 值趋势
- **删除操作**：
  - 单个删除：在供应商详情页点击删除按钮
  - 批量删除：在列表页勾选多个供应商后批量删除
  - 删除操作级联清理：供应商 → 分析记录 → 字段数据 → 原始文件

### 6. 多供应商对比

访问 `/compare` 页面：

- 勾选多个分析批次（可跨供应商、跨期）
- 对比 Z 值区间与因子构成
- 查看分组子指标明细

## 模型与阈值

| 模型 | 适用场景 | 安全线 | 灰区 | 危险线 |
|------|---------|--------|------|--------|
| Z（原始 1968，上市，5 因子） | 上市公司 | Z > 2.99 | 1.81 < Z ≤ 2.99 | Z ≤ 1.81 |
| Z′（1983，非上市制造业，5 因子） | 非上市制造业 | Z > 2.90 | 1.23 < Z ≤ 2.90 | Z ≤ 1.23 |
| Z″（1995，非上市非制造业，4 因子） | 非上市服务业 | Z > 2.60 | 1.10 < Z ≤ 2.60 | Z ≤ 1.10 |

**5 道校验门**：
- G1 复式平衡：|资产 − (负债 + 权益)| < 1 元
- G2 字段完整度：关键字段非空
- G3 非负校验：资产 / 负债 ≥ 0
- G4 量级合理性：关键字段量级合理
- G5 符号一致性：字段符号逻辑一致

---

## 三级抓取链详解

系统对资产负债表的 6 个核心字段（CA / CL / EQ / RE / TA / TL）采用逐级兜底的提取策略：

| 级别 | 方式 | 置信度 | 说明 |
|------|------|--------|------|
| L1 直接命中 | 在同义词库中直接匹配字段小计行 | 1.0 | 首选：直接抓取「流动资产合计」「资产总计」等汇总行 |
| L2 子指标求和 | 通过 FIELD_TREE 指标树，将子指标值求和 | 0.85（覆盖率 ≥25%）| 当 L1 未命中或值偏小时，将各子指标（货币资金 + 应收账款 + 存货…）求和 |
| L3 恒等式推算 | 利用会计恒等式反推 | 0.7 | TL = TA − EQ；EQ = TA − TL；TA = TL + EQ；CL = TL − 非流动负债；CA = TA − 非流动资产 |

**防误抓机制**：当报表中存在大额数值（≥10 万）时，自动过滤 1–999 的纯整数行（防止序号列被误认为金额）。

## 已知边界

- **扫描件 OCR 需 GLM_API_KEY**：未配置时，扫描件返回 `422 OCR_UNAVAILABLE`，提示配置密钥后重试；电子文本财报不受影响。
- **图片型 PDF 非确定性**：GLM-4V-Flash 对扫描件 / 图片型 PDF 的 OCR 结果可能因序号列干扰而产生非确定性，系统已通过序号防误抓机制缓解，极端情况下建议人工手填修正。
- 同源不同期财报按「同名供应商 + 多 run」归档，不做跨期自动对比计算（需手动进入对比视图）。
- 数据纯本地，无鉴权、无多用户隔离，仅限本机 / 内网使用。
